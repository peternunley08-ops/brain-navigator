# Advanced Decision System — orchestration of the three source-inspired methods

The combined system has three abilities with different evidence standards:

1. **REFINE meaning and structure** from recording 1: purposeful hierarchy, grouping, contextual delight, simplified information architecture.
2. **INTERPRET observable references** from recording 2: inspect source evidence, write a testable spec, recreate or translate, compare aligned states and correct differences.
3. **ALLOCATE attention** from recording 3: quiet foundation, high-signal focal role, controlled contrast and restraint.

Their union is not an automatic “high-design” filter. The system optimizes **task success** under the user's explicit constraints, with originality, fidelity, accessibility, correctness, and verification as separate dimensions.

## Intelligent router

For each job, identify the following without interrogating the user when context allows:

- **Artifact:** code/UI/visual/video/writing/slides/research/system/mixed.
- **User intent:** AUDIT / REFINE / BUILD / SYSTEMIZE / RECONSTRUCT (maintain v2 modes).
- **Reference relation:** no reference / inspiration / transfer behavior / faithful reproduction. In ambiguous cases, preserve the user's project identity.
- **Primary priority:** correctness, function, clarity, creative distinctiveness, fidelity, persuasion, or learning; make tradeoffs explicit.
- **Risk:** low / medium / high due to errors, public claims, accessibility, financial/legal/health/safety stakes, external integrations, or data sensitivity.
- **Available evidence/tools:** what is inspectable, editable, executable, or unverified.

Then choose a **smallest effective workflow**:

| Input condition | Dominant engine | Supporting engine | Proof required |
|---|---|---|---|
| Generic dashboard, no reference | Refinement | Attention | Completion of central task + UI states |
| Reel/screenshot to recreate | Reference | Refinement + attention only if fidelity allows | Matched states/timings, unknowns |
| “Like this, but for my brand” | Reference interpretation (principles/behavior) | Attention + refinement | Explain transferable rules; preserve branding |
| Design/color inspiration | Attention | Refinement | Focal clarity, accessible role pairs |
| Essay/research/report | Refinement + provenance | Signal budget as analogy | Argument integrity, citations, no invented claims |
| Software / AI workflow | Functional design | Refinement + reference where relevant | Runnable tests, failure and boundary cases |
| High-stakes or irreversible operations | Correctness/risk first | Other methods only when safe | Explicit constraints and dependable checks |

## Method: INTENT → EVIDENCE → MODEL → EXECUTE → VERIFY → LEARN

### 1. INTENT / preserve contract

Record (a) must-keep items, (b) desired changes, (c) user task and context, (d) fidelity stance, (e) constraints, (f) success metrics. Do not refactor correctness away in pursuit of style. For a true exact reference match, don't independently “polish” away its defining traits.

### 2. EVIDENCE / inspection

- Inspect real files/frames/records when available; identify provenance and gaps.
- Classify each critical claim: **observed, inferred, unknown**. Don't conflate screenshot with runtime behavior or a described method with shown source code.
- Set a confidence level *only for evidence quality*, not for aesthetic certainty; avoid false numerical precision.
- Map reference properties by role: composition, geometry, typography, color, state transitions, timing, trigger, content, semantics, user flow.

### 3. MODEL / causal hypothesis

Write *what should change and why*, in a falsifiable format:

> Given [observed problem], changing [specific variable] should improve [defined user outcome] because [mechanism]. We will check [test or evidence].

Examples:
- Reordering onboarding so the user sees the top action first should reduce time-to-first-success; verify via a first-use path, not just a screenshot.
- Recreating a card hover should match target x/y/rotation and opacity at aligned timestamps; compare multiple frames and input trajectories.
- Introducing a single contrasting CTA on a stable two-surface palette should make that action easier to find; verify accessibility and task discovery, not swatch aesthetics alone.

### 4. EXECUTE / controlled passes

Recommended iterative passes (skip irrelevant ones):

1. **Pass A — Truth/function:** correctness, source integrity, core mechanics, accessibility blockers.
2. **Pass B — Structure:** hierarchy, grouping, flow, grouping labels, semantics, layout.
3. **Pass C — Attention:** quiet foundation, focal moments, restrained emphasis and feedback.
4. **Pass D — Reference fidelity:** match observable details where requested; do not allow creative improvements to damage similarity.
5. **Pass E — Resilience:** errors, empty states, formats, screen sizes, test coverage, nonfunctional constraints.

Each pass should change **one to three** high-impact causes. Keep the ability to revert. When possible, preserve a before/after artifact or diff.

### 5. VERIFY / gates

**Universal non-negotiables:** no invented facts; required output created; core task correct; user constraints respected; provenance clear; no accessibility degradation; actual tests represented faithfully.

**Quality dimensions stay independent:**
- **Function**: Does the thing work?
- **Meaning**: Is it understandable and relevant?
- **Craft**: Is it coherent and deliberate?
- **Attention**: Is the right element prominent?
- **Fidelity**: Does it match the requested reference properties?
- **Trust**: Is it accurate, safe, and evidence-backed?

A low score in one dimension cannot be hidden by high scores elsewhere. In faithful reconstruction, a beautifully original redesign can still be a fidelity failure.

**Risk-adjusted testing:**
- Low risk: core path + one relevant check.
- Medium: core path + edge case + accessibility/data review.
- High: explicit acceptance criteria, independent validation where tools allow, failure-mode review, rollback path if relevant. Don't imply that one pass of AI self-review constitutes independent verification.

### 6. LEARN / stop rules

Capture the effective rule as an editable token, component, pattern, test, or reusable prompt. Maintain a short decision log with **issue → change → evidence → result → next action**.

Stop when user success gates pass and further edits add little expected benefit, or when evidence/tool limits prevent honest confidence. Don't run an infinite self-improvement loop; seek a useful shippable result.

## Deterministic conflict resolution

1. Safety, privacy, legal/rights, and explicit user constraints come first.
2. Working behavior and factual correctness must not be traded for decoration.
3. In faithful RECONSTRUCT, the requested source relationship takes priority over personal aesthetic taste.
4. In inspiration/REFINE, the user's product identity and user needs outrank the reference's literal colors, logos, and assets.
5. Accessibility and semantic status may require additional colors or visual treatments; don't impose a “three colors only” rule.
6. If quantitative tests and human perception disagree, explain both; don't declare either an infallible oracle.

## Useful additions beyond all three Reels (original framework)

- **A design decision record** so changes don't drift across iterations.
- **Acceptance tests** that describe what success means before polishing begins.
- **Role-based tokens** that keep palettes/components consistent and portable.
- **Observation confidence** to prevent hallucinating reference properties.
- **Risk and accessibility gates** that supersede cosmetic optimization.
- **A minimal reproducible quality check** for each medium: functional path, document evidence, video timing, or color contrast.
- **Maintenance plan**: reusable variants and tests instead of one-off demonstrations.

These are skill extensions, not techniques claimed to be shown in the three videos.
