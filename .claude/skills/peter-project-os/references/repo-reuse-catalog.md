# Recording-derived repository leads — not an install bundle

## What was actually inspected

The supplied ZIP contained a screen recording approximately 17.5 seconds long. Visual frames were sampled across the clip, with denser samples in the changing repository cards. Audio was not transcribed. The recording starts at card 2/40, shows cards 2–10, and displays category labels for harness, skills, memory, tools, and token bill. It does not expose all 40 repository identities. No missing entries, star counts, license claims, or performance claims have been inferred as facts.

The nine visible owner/repository identities below were checked against their public GitHub landing pages on November 15, 2026. This verifies discovery leads, not code safety, current release suitability, exact module licensing, or successful integration. Revalidate the chosen revision and inspect actual files before use. No third-party source or installers are bundled in Anti-Slop.

## Examples of decisions

- A React landing page already has browser inspection and an established component system: use Anti-Slop's own design/visual references; no new harness, second browser, or full UI kit.
- A report needs a format capability absent from the host: inspect a relevant artifact skill and its actual dependencies/license, then activate only the compatible module if permitted.
- A project has a confirmed complex parser gap: search beyond this agent-focused catalog for an appropriate maintained parser package; do not force one of these nine repositories into an unrelated need.
- A long-running workflow system is the project itself: a platform may be justified, but this is a distinct architecture decision with an explicit resource/deployment plan.

These decisions illustrate the selection method; they do not preapprove an upstream version. User-specified repository preferences can narrow search but cannot eliminate compatibility, provenance, permission, and footprint checks.
